Windows: Certificate Errors When Checking for Updates

Applies to: Lignomat Sensors on Windows 10 and Windows 11
Updated: October 25, 2026
Audience: End-users and support technicians

Download PDF

Problem / Symptoms

Use this note if checking for updates reports a network problem and the app's system log includes:

UpdateService: GitHub check error - HandshakeException: ...
CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate

This means the app cannot verify the HTTPS connection to GitHub. It does not necessarily mean your internet connection is down or the installer is broken.

Likely Cause

Windows may be missing a trusted certificate, possibly due to a missed update, a security product, a network proxy changing certificates, or an organizational IT policy.

Windows can retrieve some missing trusted certificates automatically. The app's networking runtime may not trigger that retrieval. Connecting through Windows PowerShell may help, but it is not a guaranteed repair.

Recommended Steps

This method uses Windows' networking stack and may prompt Windows to retrieve the missing trusted certificate. Administrator access is not normally needed. You do not need to reinstall the app or enter any credentials.

  1. Fully close Lignomat Sensors, including any minimized instance.
  2. Open the Start menu, type Windows PowerShell, and open it. Use Windows PowerShell, not Command Prompt.

  3. Copy and paste the single command line below, then press Enter. Scroll horizontally if needed to see the entire command.

    Invoke-WebRequest https://api.github.com -UseBasicParsing -TimeoutSec 30

    Capitalization does not matter for this command: PowerShell command and option names, and the URL's hostname, are case-insensitive. Spelling, punctuation, and spaces separating the parts do matter. Use ordinary hyphens (-) before option names, and do not insert spaces inside the URL or names. Multiple spaces between parts are okay.

    This checks HTTPS trust for the same hostname the app uses. -UseBasicParsing avoids legacy parsing issues in Windows PowerShell, and -TimeoutSec 30 prevents an indefinite wait.

  4. Allow about 30 seconds for the request. If it remains stuck, press Ctrl+C to cancel.
  5. Interpret the result:
ResultMeaning and next action
StatusCode : 200 and technical textWindows connected successfully. Continue with Confirm the Result below.
An HTTP error such as 403 or 429, without a certificate errorHTTPS connected, but the server rejected the request, possibly because of a request limit. This does not prove the app is repaired. Wait before retrying and retain the error for support.
A certificate, trust relationship, or secure-channel errorThe connection still has a trust or TLS problem. Follow If the Problem Continues below.
A timeout, name-resolution error, or connection failureCheck the internet connection, firewall, and proxy. This is not confirmation of a certificate problem.

Confirm the Result

  1. Reopen Lignomat Sensors.
  2. Check for updates again.
  3. Confirm that the certificate-related network error no longer appears. The app may offer an update or report that no newer version is available.

Restarting the app matters: it may have loaded its trusted certificates before Windows retrieved the missing certificate. A successful PowerShell request alone does not prove that the app's connection is repaired.

If the Problem Continues

  1. Check the date, time, and time zone. Open Settings > Time & Language > Date & time and correct any errors.
  2. Check Windows Update. On Windows 10, open Settings > Update & Security > Windows Update > Check for updates. On Windows 11, open Settings > Windows Update > Check for updates. Install updates available for the PC and restart if requested.
  3. Try a different network, such as a phone hotspot, if possible. If the app works there, ask your technician to investigate the original network's proxy, firewall, or HTTPS inspection.
  4. Contact support or your IT technician if the problem remains. Provide:
    • The installed Lignomat Sensors version.
    • The system-log error and the time it occurred.
    • The PowerShell result, if tried.
    • Whether a different network changed the result, if possible.

Do not send passwords, access keys, or other credentials.

Technical Notes

  • Windows PowerShell and the app use different TLS implementations. The PowerShell request may retrieve a certificate that the app can then use, but it does not guarantee that the app will succeed.
  • Check whether your organizational policy disables automatic root-certificate updates or blocks Microsoft's certificate-update infrastructure.
  • Do not disable certificate verification, bypass browser warnings, or import certificates from unverified sources. Do not disable security software as a routine repair.
